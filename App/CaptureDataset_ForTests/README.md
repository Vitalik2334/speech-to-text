# Інтеграційні тести розпізнавання — повний пайплайн

Інтеграційні тести проганяють **справжній** `DictationApp` і **справжню** модель
на **твоїх власних записах** і перевіряють, що якість розпізнавання не погіршилась.

Пайплайн коротко:

```
1. Записати кліпи      →  UAFastConformer.py --capture   →  Tests\clips\NNNN.wav + NNNN.json
2. Розмітити кліпи     →  вручну                          →  Tests\clips\NNNN.txt
3. Зафіксувати baseline →  pytest --update-baseline       →  Tests\baseline.json
4. Перевіряти зміни    →  pytest -m integration           →  pass / fail + звіт
```

Усі команди нижче — у **PowerShell**, з **кореня проєкту**:

```powershell
cd C:\Users\Vitalik\PycharmProjects\VoiceToText
```

---

## 0. Один раз: підготовка

`jiwer` (рахує CER/WER) стоїть у `.venv`, але його немає в `pyproject.toml`.
Додай його, щоб `uv` не загубив пакет при наступній синхронізації:

```powershell
uv add jiwer
```

## 1. Записати кліпи

Запусти застосунок з прапорцем `--capture`:

```powershell
$env:PYTHONPATH = "."
uv run App\UAFastConformer.py --capture
```

> `PYTHONPATH = "."` потрібен, бо застосунок імпортує
> `App.CaptureDataset_ForTests.dataset_capture` від кореня проєкту.
> PyCharm додає корінь сам (Run → Edit Configurations → Parameters: `--capture`).

У консолі має з'явитись:

```
[capture] Збір кліпів УВІМКНЕНО → C:\Users\Vitalik\PycharmProjects\VoiceToText\Tests\clips
```

Тепер диктуй як завжди. Після кожної фрази:

```
[capture] збережено 0001.wav (3.2 с)
```

і в `Tests\clips\` з'являються:

| Файл | Що це |
|---|---|
| `0001.wav` | звук з мікрофона: 16 кГц, моно, PCM16 |
| `0001.json` | службове: що розпізнала модель (`"recognized"`), модель, налаштування, дата |

Порада: одразу після кожної фрази запиши собі, що саме ти сказав — знадобиться на кроці 2.

Що варто записати (10–30 кліпів достатньо для старту):
- звичайні короткі й довгі фрази;
- числа, дати, англійські слова, терміни — те, де модель помиляється;
- 2–3 записи **без слів** (тиша, кашель, клавіатура) — для перевірки, що модель не вигадує текст.

Дуже короткі натискання не зберігаються — це нормально.

## 2. Розмітити кліпи: створити `NNNN.txt`

Для **кожного** `NNNN.wav` створи поруч `NNNN.txt` з тим самим номером:

```
Tests\clips\
  0001.wav   0001.json   0001.txt
  0002.wav   0002.json   0002.txt
```

**Вміст `.txt`** — дослівно те, що ти сказав, один рядок, UTF-8 (Блокнот підходить):

```
Привіт, сьогодні я перевіряю, як працює розпізнавання мови.
```

Правила:

- **Регістр і пунктуація не важливі** — перед порівнянням усе зводиться до нижнього
  регістру, пунктуація прибирається, апострофи уніфікуються.
- **Слова — точно як сказано.** Це еталон, з яким порівнюється модель.
- **Не копіюй сліпо `"recognized"` з `.json`.** Можна взяти як чернетку, але виправ
  помилки моделі — інакше тест вважатиме помилку правильною відповіддю.
- **Числа пиши в тій формі, у якій їх видає модель** (цифрами чи словами — глянь у `.json`).
  `25` і `двадцять п'ять` рахуються як різні слова.
- **Порожній `.txt`** (0 символів) — для запису без мови. Тест перевірить, що модель
  на ньому нічого не видала.
- `.wav` **без** `.txt` тест просто пропускає.

### Необов'язково: теги (`manifest.json`)

Щоб бачити точність окремо по групах кліпів, створи `Tests\manifest.json`
(поруч з текою `clips`, не всередині):

```json
{
  "0001": ["numbers"],
  "0002": ["english", "fast"],
  "0003": ["noise"]
}
```

Назви тегів — довільні. Теги довжини `short` / `medium` / `long` ставляться автоматично.
Тест `test_cer_per_tag_no_regression` падає, якщо якась група погіршилась більше ніж на 4%.

## 3. Зафіксувати baseline

Перший прогін — запам'ятати поточну якість як точку відліку:

```powershell
uv run pytest -m integration --update-baseline
```

Результат:
- `Tests\baseline.json` — збережені CER/WER по кожному кліпу, тегу і загалом;
- `Tests\reports\...` — текстовий звіт (він же друкується в кінці як «ЗВІТ РОЗПІЗНАВАННЯ»).

Тести регресії в цьому прогоні будуть `skipped` («baseline щойно оновлено») — так і має бути.

Подивись звіт: якщо CER на якомусь кліпі дивно великий — найчастіше помилка в `.txt`.
Виправ і повтори `--update-baseline`.

---

## 4. Перевіряти зміни

Після будь-яких змін у коді (гейт тиші, нарізка, склейка, налаштування):

```powershell
uv run pytest -m integration
```

Що перевіряється:

| Тест | Падає, якщо |
|---|---|
| `test_cer_no_regression` | загальний CER гірший за baseline більш ніж на 2% |
| `test_wer_no_regression` | загальний WER гірший за baseline більш ніж на 3% |
| `test_cer_per_tag_no_regression` | CER якогось тегу гірший більш ніж на 4% |
| `test_negative_clips_empty` | на кліпі з порожнім `.txt` модель видала текст |
| `test_streaming_vs_single_pass` | потоковий цикл гірший за один прохід по файлу більш ніж на 3% CER |
| `test_events_order` | порушено порядок подій (`final_audio`, `partial_text`, `final_done`) |

Допуски — константи на початку `Tests\test_recognition_integration.py`.

Швидкі (не інтеграційні) тести окремо:

```powershell
uv run pytest -m "not integration"
```

---

## Коли знову запускати `--update-baseline`

- додав нові кліпи, видалив старі або **виправив** якийсь `.txt`;
- змінив модель або квантизацію;
- свідомо погодився з новим рівнем якості (наприклад, після покращення).

Тести самі підкажуть: `skipped: набір кліпів змінився (...) — запустіть з --update-baseline`.

Не оновлюй baseline лише для того, щоб «позеленіли» тести після погіршення — тоді регресія
стане новою нормою.

## Де що лежить

| Що | Де |
|---|---|
| Папка датасету (кліпи, baseline, звіти) | `VoiceToText\Tests\` |
| Звідки береться цей шлях | `DEFAULT_DATASET_DIR` у `dataset_capture.py` (ця тека) |
| Перевизначити шлях (і для застосунку, і для тестів) | змінна `$env:VTT_DATASET = "D:\інша\тека"` |
| Увімкнення capture | `--capture` або `CAPTURE = True` в `App\UAFastConformer.py` |
| Запис кліпів | `DatasetCapture` у `dataset_capture.py` |
| Завантаження кліпів для тестів | `load_dataset()` у `Tests\recognition\harness.py` |
| Метрики й нормалізація тексту | `Tests\recognition\asr_metrics.py` |
| Baseline і звіт | `Tests\recognition\report.py` |
| Тести | `Tests\test_recognition_integration.py` |
| Опція `--update-baseline` | `Tests\conftest.py` |

## Якщо тести `skipped`

| Причина у виводі | Що зробити |
|---|---|
| `немає розмічених кліпів` | немає пар `.wav` + `.txt` у `Tests\clips\` — крок 1–2 |
| `baseline.json ще немає` | крок 3 |
| `набір кліпів змінився` / `baseline записано для ...` | `--update-baseline` |
| `не вдалося підготувати DictationApp / модель` | модель не завантажилась — перевір, що застосунок сам запускається |
